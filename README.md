# DAYTRACE

Фоновый трек не включён в публичные исходники. Чтобы включить фоновую музыку в своей копии, поместите аудиофайл, на распространение которого у вас есть права, в `dist/assets/ambient.mp3`. Остальные функции дневника доступны без него.

Личный фотоальбом с заметками, снимками и музыкой. После знакомства по имени открывается запись сегодняшнего дня. Дата в редакторе позволяет вернуться к любому прошедшему дню.

## Запуск

Выполните команду `node serve.mjs` в корне проекта и откройте [дневник](http://127.0.0.1:4173/). Нужен Node.js 18 или новее. Папку `dist` можно раздать любым статическим веб-сервером.

## Дневник

- Для сохранения нужны заметка и от одного до четырёх снимков. Принимаются JPG, PNG и WebP до 12 МБ каждый. Для просмотра создаётся копия до 1800 пикселей по длинной стороне. Дневник сохраняет также исходный файл нового снимка и включает его в ZIP.
- Музыка необязательна. Можно приложить аудиофайл до 20 МБ, добавить название или ссылку. Файл и прямую ссылку на поддерживаемый браузером формат проигрывает общий плеер. Ссылка на страницу музыкального сервиса открывается отдельно.
- «Альбомы» показывают двенадцать сезонных обложек и число сохранённых записей под каждой. Нажатие на обложку открывает выбранный месяц. Внутри месяца снимки расположены по датам. На развороте видны до 14 дат и последняя карточка с серым плюсом. Серый вопрос открывает пустую прошедшую дату, а плюс открывает свободный день. Диапазоны под снимками переключают развороты. Выбранная запись открывается внутри вертикальной ленты всего месяца. У фотографий работают боковые области, клавиши со стрелками и свайпы.
- Плеер запускается кнопкой или при наведении мыши на снимок, когда в дневнике ничего не играет. Браузеру может понадобиться первый клик на странице для разрешения звука. В настройках можно выключить воспроизведение при наведении и включить вечернее оформление.
- Из ленты можно вернуться в редактор и продолжить запись.

## Хранение и статистика

Профиль, записи и прикреплённые файлы хранятся в IndexedDB текущего браузера. Для обновления используется прежнее хранилище дневника. Новые альбомы открываются пустыми. По желанию в профиле можно заполнить данные для статистического ориентира. Расчёт использует показатели ожидаемой продолжительности жизни при рождении за 2025 год для Казахстана и 2024 год для остальных стран с доступными данными. [Бюро национальной статистики Казахстана](https://stat.gov.kz/ru/industries/socialstatistics/demography/publications/281575/) · [Всемирный банк](https://data.worldbank.org/indicator/SP.DYN.LE00.IN)

Шрифты Cormorant Garamond и Bad Script поставляются с приложением. Их лицензии OFL находятся в папке assets. Сезонные фоны созданы по художественному референсу проекта.


## Умное оформление и отчёты

1. Запустите `npm start` и откройте дневник по адресу, который напечатает сервер. На опубликованном сайте шаг запуска не нужен.
2. В редакторе раскройте «Оформить день», включите умное оформление и сохраните запись. При первом включении браузер скачает модель с Hugging Face. Для первого запуска нужен интернет, современный браузер с WebAssembly, место для кеша и оперативная память. После загрузки файлы модели повторно используются из кеша этого браузера.
3. В ленте откройте «Почему этот день выглядит так?». Здесь видны источник, связь оформления с записью и кнопка для изменения названий, палитры, настроения и пояснения.
4. Откройте месяц и нажмите «Отчёт месяца». ИИ оценивает эмоциональный тон описанных дней по общей шкале 0–100. Звезда отмечает максимальный балл, при равенстве выбирается первая дата. Цвет от красного через жёлтый до зелёного соответствует среднему арифметическому, округлённому до десятых. После изменения данных для оценки отчёт можно собрать заново.

Модель выполняется на устройстве через wllama. Сервер раздаёт статические файлы. Внешнее соединение используется для загрузки публичных весов. Текст, миниатюры и результаты вычислений остаются в браузере. Модель получает сведения о музыке из полей дневника и имени файла. Страницы музыкальных сервисов не открываются для анализа. Для ранжирования длинных заметок используются их начало и конец. Если модель недоступна, пользователь отменил загрузку или ответ не прошёл проверку, дневник подписывает результат как локальное оформление по правилам.

Схемы и проверка результата находятся в `dist/director-contract.js`, загрузка модели, vision и вывод по JSON Schema в `dist/director-model.js`, извлечение цветов и вычисления в `dist/director-data.js`. В `dist/director-ui.js` и `dist/director.css` находятся оформление страницы, редактор параметров, примеры и месячный отчёт. Исходники загрузки, навигации и IndexedDB остаются в прежних файлах `composer.js`, `albums.js` и `app.js`. `npm test` запускает проверки контракта и рейтинга, `npm run build` проверяет готовую статическую поставку.

## Лёгкий подбор оформления (без модели)

Умное оформление больше не скачивает модель. Настроение определяется по словам записи: тяжёлые слова («плохо», «не получилось», «тяжело», «не», «без») дают грусть, радостные («ура», «получилось», «да») дают радость. Также учитываются слова злости, энергии, спокойствия и ностальгии и характер музыки. Если слов нет, выбирается случайная эмоция из злости, энергии, спокойствия и ностальгии. У каждой эмоции заранее заданы палитра, композиция, несколько названий и описаний (выбираются случайно) и набор минималистичных значков вокруг снимка.
